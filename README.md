# BoB Web

첨부 랜딩 시안을 기반으로 만든 한국어 반응형 랜딩페이지와 브라우저 로컬 웹앱입니다.

## 실행

Node.js 22 이상에서 `npm run dev` 실행 후 http://127.0.0.1:4173 으로 접속하세요. 앱 런타임에는 패키지 설치가 필요 없습니다.

`npm run build`는 정적 배포용 `dist/`를 생성합니다. 웹 서버의 document root를 dist로 지정하면 됩니다. 해시 라우팅이므로 별도 SPA rewrite는 필요하지 않습니다.

개발 검증: `npm install`, `npm run lint`, `npm run typecheck`, `npm test`.

## 기능

- 랜딩: 첨부 HTML의 브랜드 이미지, 설명, 사용 흐름
- 물건 수동 등록, HTTPS 상품 링크/최대 10장 이미지 분석, 일괄 등록 전 편집·선택·할인 비교
- 등록 다음 날부터 가격별 3/7/14일 관찰, 판매 마감일 반영, 결과와 Buy/Bye/보류
- 구매 전·후 선택/숫자/문장 질문, 오늘 답변 수정, 로컬 기본 질문과 결과 요약
- 구매 후 사용 점검, 목표와 참은 금액, 가계부, 리포트, 할인 비교
- 브라우저 로컬 저장, JSON 백업·복원, 저장 실패 안내

## 데이터와 연동

로컬 원장은 localStorage의 `bob.web.v1` 키에 버전 2 형식으로 저장합니다. 새 물품 등록·구매 결정·사용 점검은 서버에도 반영합니다. 매일 질문과 답변 원문은 로컬에 두고 결과 요약 요청 시 전송합니다. 목표·예산·즉석 소비·추가 소득은 로컬 기록입니다. 서버 등록은 중복 방지 키를 보관해 실패 후 같은 요청으로 재시도합니다. 직접 입력한 새 물품도 서버 등록을 완료해야 시뮬레이션이 시작됩니다.

기존 로컬 물품은 자동 재등록하지 않습니다. 브라우저·기기 간 자동 동기화는 없으며, 웹 백업 및 모바일 BOB 백업 v1~v4 가져오기를 지원합니다. 웹 백업을 모바일로 역변환하지는 않습니다. 백업은 서버 소유권 ID와 인증 정보를 제외하므로 복원 물품은 로컬로 관리합니다. 모바일 내부 파일 경로 이미지는 다시 선택해야 합니다. 미완료 서버 등록이 있는 모바일 백업은 해당 등록을 마친 뒤 가져오세요.

첫 v2 전환 전 원본은 `bob.web.v1.before-v2`, 복원 전 사본은 `bob.web.v1.before-import`에 보관합니다. 과거 답변·지출·달성 목표는 보존합니다. 옛 미완료 목표만 전환일부터 예산 기반 적립을 새로 시작하며 과거 저축액을 추정하지 않습니다. 로컬 초기화는 이 사본들도 지우며 서버 기록은 삭제하지 않습니다.

목표 계산은 BOB_FE의 자유 소비 예산·실제 지출·달력 일수 모델을 따릅니다. 참기/Bye 금액은 행동 리포트에 기록하지만 목표에 즉시 가산하지 않습니다. 웹의 추가 소득은 잔액에 반영하되 목표 계산의 월 예산에는 자동 포함하지 않습니다. 목표 예측에도 반영하려면 월 예산을 수정해야 합니다.

알림은 권한을 허용한 페이지가 열려 있을 때 서울 시간 저녁 8시 이후 제공합니다. 닫힌 브라우저의 푸시는 지원하지 않습니다.

## 검증 한계

단위 테스트는 금액 보존·윤년·이월·조기 구매·요약 조건·재시도·백업 변환을 검사합니다. 격리 브라우저에서 API 쓰기를 대체한 응답으로 등록 실패 복구, 구매 전/후 답변 및 수정, 목표, 7개 주요 화면의 데스크톱/모바일 레이아웃을 검증했습니다. 프로덕션 사용자 데이터로 새 구매나 지출을 생성하는 검증은 하지 않았습니다.

구매 후 실제 사용 일수는 빈도 응답의 대표값입니다. 예상값은 마지막 질문의 30일 예상 사용일수를 14일로 환산하며, 유효 응답률 70% 이상·예상값 존재·조기 구매 아님 조건을 모두 충족해야 비교합니다. 실제 배포 서버는 조기 Buy만 허용하므로 서버 연결 물품의 Bye는 종료 후에 제공하며 이전 로컬 물품의 조기 Bye는 유지합니다.

## 실제 백엔드 연결
기본 서버는 https://bob-be.vercel.app 입니다. npm run dev는 /api/v1 요청을 해당 서버로 전달합니다. Vercel 배포는 vercel.json의 동일 출처 rewrite를 사용합니다. 다른 정적 호스팅에서는 /api/v1 프록시를 별도로 설정해야 합니다. 사용자 지정 서버는 CORS 허용이 필요합니다. 게스트 토큰은 서버별 별도 localStorage 키에 보관하며 백업에는 포함하지 않습니다. 기존 리소스의 인증 오류에는 새 게스트를 만들어 소유권을 잃지 않도록 자동 재발급하지 않습니다.

배포된 OpenAPI에서 현재 사용하는 경로와 메서드를 확인했습니다: POST guest-sessions, item-drafts, product-url-drafts, cart-extractions, items/batch, simulations/:id/local-question, purchases/:id/local-question, simulations/:id/result-summary; PUT items/:id/decision, purchases/:id/review. 예산·목표·가계부·리포트용 서버 API는 호출하지 않습니다.

## 배너 3D 모델
mascot-brown.glb는 제공된 GLB를 scripts/prepare_mascot.py로 변환한 4.7MB 단색 모델입니다. 색은 #5A3A28, CSS 불투명도는 45%입니다. model-viewer 4.0.0 런타임과 Apache 2.0 라이선스를 함께 로컬 배포합니다. 원본 재변환: `python scripts/prepare_mascot.py 원본.glb mascot-brown.glb`. WebGL을 지원하는 브라우저가 필요합니다.

## 배포

프로덕션 주소: https://bob-web-chi.vercel.app

Vercel 프로젝트: `mas-f1f6/bob-web`. `vercel.json`의 `framework: null`은 브라우저용 app.js가 Node 서버 진입점으로 오인되는 것을 막습니다. `dist`의 정적 파일과 `/api/v1` 백엔드 프록시를 배포합니다.

다시 배포: `npx --yes vercel@latest deploy --prod --yes --scope mas-f1f6`. `.vercelignore`는 배포에 필요한 파일만 허용합니다. `.vercel`과 `.env*`는 커밋하지 않습니다. GitHub `2026-InThon-Team12/BOB_WEB`의 `main`에 push하면 Vercel 프로덕션으로 자동 배포됩니다.

로컬 주소와 배포 주소의 브라우저 저장소는 분리되어 있습니다. 기존 기록을 옮기려면 로컬 설정에서 백업을 다운로드한 뒤 배포 사이트 설정에서 복원하세요.
